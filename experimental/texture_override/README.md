# Experimental opt-in DDS texture overrides

Original MIT tooling. No game assets, pack downloads or AI inference. This directory is **not integrated into the standard build**. Its renderer hook is a reviewable, unapplied patch; native library tests do not prove a translated-game upload or acceptable frame times.

`texture_override.c` is a standalone library without GL dependencies. It receives an existing SHA-256 implementation as a callback, reads a flat `manifest.index`, validates legacy DXT1/3/5 DDS files, and returns immutable compressed mip payloads. It limits mappings to 128, dimensions to 1024, source scaling to 1–2x, source-hash input to 2 MiB, each DDS file to 2 MiB, and retained payload to 64 MiB. It caches both validated files and failed lookups for the process lifetime. No file reload occurs during ordinary binds; restart to change a pack. A read temporarily allocates up to 2 MiB plus the payload, and source hashing temporarily allocates a bounded input copy. These overheads are additional to retained payload and GPU/driver allocation.

Files are opened relative to a directory descriptor with `openat`, `O_NOFOLLOW` and nonblocking reads; index and data filenames must be flat, safe basenames. The native path checks regular-file type. The translated guest path instead uses the existing narrow `posix_fstat` import, which exposes directory and size fields: it rejects directories, zero-sized files and oversized files, including ordinary FIFOs/devices with no positive payload size. That guest import does not expose full file type, so use only ordinary immutable files in a user-controlled pack directory. No `..`, slash, drive paths or data-file symlinks are allowed. The explicitly selected root directory itself may be a user-selected symlink. The index requires checksums, source dimensions and unique source keys. A failed pack/file produces an original-texture fallback; provenance still requires human review.

The hash contract matches `scripts/texture_manifest.py`: SHA-256 of the domain string `HALO-XGPU-TEX-V1` including a trailing NUL, little-endian format/size words, and exact original texel storage. This is deliberately not a PC TexMod identity. Runtime files and index must stay unchanged while the process runs.

The index uses a preallocated 256-slot open-addressed table for at most 128 entries: expected O(1) lookup with a fixed bounded worst case. Source/DDS hashing is O(bytes), DDS mip validation is O(mip levels), and all work occurs on first pack load or a texture-cache upload/invalidation. Ordinary binds add no hashing, file I/O or allocation. Capacity exhaustion rejects later entries deterministically; retained DDS payloads do not churn through eviction. The native fixture reports 35,872 bytes of fixed pack metadata and verifies it against the C library's `sizeof`; translated guest ABI size must be checked in the integration build. Its 8x8 DXT1 full-mip fixture retains 56 payload bytes, calls the DDS hash once on 184 file bytes, and performs no additional hash call or payload allocation on repeat lookup after the file is removed. These operation/allocation checks do not measure FPS or total process/GPU memory.

## Integration review

To test an experimental game build, copy only `texture_override.c` and `.h` into `port/linux/src/` of a separate upstream checkout with this project's macOS overlay, then review/apply `xbox_textures-hook.patch`. The patch targets the [upstream Xbox texture upload/cache implementation](https://github.com/cybersecurity/halo-ce-universal/blob/0ef2ed7dc7a96299ea7d8d02a1bc3f9fb1c231af/port/linux/src/xbox_textures.c). It includes the library in that guest build unit with `TXO_GUEST_ABI`, reuses the existing `p2p_sha256` and narrow `posix_fstat` import, and needs a recompiled guest plus a matching lift/native executable. Do not reuse an old translated executable with a changed guest. The patch is macOS-gated and adds no custom host import or syscall. It does exercise musl's existing `openat`, `read`, `close`, allocation and scanning paths; their translated execution still needs integration testing.

Without `HALO_TEXTURE_PACK`, the upload hook immediately retains original textures and does not hash/read pack data. Setting that variable to a directory explicitly opts in. Only normalized-coordinate, compressed, nonpalettized 2D textures that already have mipmaps are eligible. The index is an author-maintained color-texture allowlist: the low-level format alone cannot prove a texture is not a lightmap, multipurpose shader map, normal map, or dynamically generated image. Review semantic usage before including an entry. The replacement must retain the original DXT format, source aspect ratio and alpha meaning. The hook changes GPU upload dimensions only and preserves original guest records, cache identity and shader coordinate interpretation. Nonmatches, invalid files, budget failures, unsupported S3TC and GL errors use the original upload.

Optional `HALO_TEXTURE_KEY_LOG=1` logs eligible source keys on upload for local mapping. With no pack it is diagnostic only and adds hashing overhead; turn it off for baseline/performance measurements. Existing `debug.texture_dump_directory` can support local visual identification, but dumped textures are proprietary local outputs and must not be committed or redistributed. Logging keys does not identify semantic use automatically.

The prototype has no GPU-residency accounting, asynchronous preload, eviction of retained DDS payloads, or draw-time reload. Its 64 MiB budget bounds compressed retained input, not all unified memory use. Separate guest resources containing identical original texture storage can map to the same retained DDS while creating multiple GPU copies; those GPU copies remain subject to the renderer's existing idle-eviction policy. A production memory cap needs replacement-byte accounting on GL-cache creation/reupload/deletion, or shared GPU replacement objects with explicit ownership. Its hook logs dimensions and bytes, but a benchmark needs separate upload-time instrumentation. File hashing/loading occurs during cache upload and may stall a frame. Before shipping the hook, run native and translated fixtures, inspect GL fallback behavior, and compare cold/warm frame-time distributions at both target resolutions. Synthetic replacements prove plumbing only, not HD artistic quality.

## Fixtures

`python3 tests/test_texture_override_native.py` compiles the standalone library with strict native compiler warnings into an owned temporary directory and runs 18 synthetic fixtures: nine using direct native file-stat checks and the same nine using an independent mock of the narrow guest-stat interface. It covers cross-language storage hashes, matching/fallback, checksum mismatch, retained-cache reuse, negative-cache behavior, symlink/traversal rejection, duplicate indexes, budget failure, DDS format/dimension/mip rejection, hash-table collisions, metadata size and an offline-index compiler round trip. The mock tests the library's ABI branch, not an actual translated guest or native host import. No assets are downloaded or retained.

`python3 tests/test_texture_manifest.py` checks the independent offline DDS/JSON validator. Generate `manifest.index` from a legitimate, locally authored flat pack using the explicit `--runtime-index` option. Neither fixture invokes the game or applies the renderer patch.
