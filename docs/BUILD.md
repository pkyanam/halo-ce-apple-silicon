The repository is a build/tooling overlay, not a copy of the reconstructed Halo source tree. It fetches cybersecurity/halo-ce-universal at `0ef2ed7dc7a96299ea7d8d02a1bc3f9fb1c231af`, applies the focused source patch, then overlays the native host/build implementation. XboxRecomp is independently fetched at `051a128df5ec27ef14f1ceaaead11c5457321eef` and receives the recorded translator/runtime patch. Source vendors keep their upstream notices.

Source/runtime/musl and Capstone inputs are pinned. Homebrew supplies the platform toolchain/libraries; exact installed versions and the host SDK are recorded in local build provenance. Repeating the pipeline does not promise identical artifact hashes across different toolchains or SDKs.

The build creates i386 musl headers from a SHA-verified 1.2.5 archive, produces MSVC semantics headers from source, compiles game/platform/math/libc object manifests, resolves imports into an ELF, and translates functions into ARM64 C shards. CMake compiles the host plus those shards with native optimization level 2 and explicit macOS 14 deployment target. Packaging reads ARM64 deployment load commands for the engine and each required dylib, then records their maximum requirement (and the native macOS 14 API floor) in the app metadata; selecting a lower target does not make newer libraries compatible with older systems. The package builder copies the engine, ELF, resources and recursively required non-system libraries, rewrites Mach-O linkage, signs the result, and performs a no-launch `--check`. No precompiled game artifact or machine-local source path is needed.

For upstream development, the optional `--source-checkout` mode consumes an existing checkout **with the Mac target integrated**:

```bash
./setup.sh "/path/to/your/Halo Xbox.iso" --source-checkout ../halo-ce-universal --jobs 4
```

It snapshots current indexed file contents into a fresh external build directory, preserving working modifications, staged additions and working deletions. Stage newly added build inputs first; untracked files are excluded. This mode skips Halo fetching, the Mac source patch and overlay replacement, so current upstream and native changes remain intact. It does not alter the source checkout. Generated output, game assets and binary artifacts are excluded; symlink source inputs are rejected. XboxRecomp/musl dependencies still use public pins. Portable provenance records the checkout commit and relative file hashes, not the checkout's machine path. The default installer mode continues to fetch the pinned upstream source and apply the reviewed patch/overlay. Original synthetic mode tests verify these distinctions without a game build or network download.

The installed native launcher prepares user state, verifies bundled engine/ELF hashes, holds a single-instance lock across exec, and activates an existing process when launched twice. It runs the native engine in the same process. Diagnostic capture/test input requires explicit opt-in; normal app startup strips those controls. All engine-required disc data is sealed inside Contents/Resources/GameData. A writable user-state overlay links its map/movie directories to the current bundle path; generated language/cache/save/debug files stay outside the signed app. Asset hashes and cache versions are recorded, and --check hashes the complete data set. Existing user data and the source ISO are preserved.

The genuine USA Rev1 tree contains Halo maps/Bink movies, the original executable and an unrelated Xbox demo package. Fonts and localization are map tags; the native engine replaces the executable and does not run the bonus demo. Optional debug/config inputs are not disc requirements. Localized map directories and language-suffixed Bink movies are included when present.

The XDVDFS reader accepts partition bases 0, 0x0FD90000, 0x02080000 and 0x18300000, bounds-checks directory/file extents, rejects cyclic trees and unsafe/duplicate paths, and extracts only retail map caches in maps/ and recognized localized maps_* directories, plus bink/*.bik. Cache headers must identify the recognized Xbox Halo builds. Synthetic fixtures cover XISO/Redump extraction, PAL recognition, PC rejection, unsafe names, loops, truncated images and unknown cache builds. Genuine USA Rev1 header/tree reads were checked against a 29-file asset inventory with full-file hashes; validation used ranged image reads rather than a full image download.

CI runs original synthetic fixtures on Linux and a fresh installer build on the public macOS ARM64 runner. The build job creates a synthetic XDVDFS image containing only generated test headers, fetches pinned public source/tool dependencies, compiles and signs the app, and performs static `--check`. It never downloads a game image, launches Halo or uploads generated game code/binaries. Synthetic data is sufficient for packaging checks, not gameplay. The macOS workflow must actually pass before its status is treated as validation evidence.

The native pre-link guard checks all generated guest definitions against host archive definitions and undefined references, including archive members omitted by the linker. Its regression reproduces silent helper shadowing and catches accidental native library interposition. Native build fixtures also reproduce Darwin connected-UDP send errors and verify exact-peer retries, aliases and mismatched-peer rejection, then exercise the source UI condition classifier and SDL virtual Xbox/DualSense devices through native tokens and the actual freshly translated guest XInput adapters. The connected-UDP retry applies only to EISCONN with the actual connected IPv4/port peer; other destinations retain the OS error. These tests synthesize input and controlled fixture services, not game assets; they do not launch the game or establish physical Bluetooth compatibility.

For a bounded two-engine multiplayer reproduction, run from the fetched source directory with your own bundled map data and an existing non-loopback local IPv4 address:

```bash
python3 tools/run_macos_multiplayer_pair.py \
  --binary build/native/halo_macos_aot \
  --elf build/macos-aot/halo_guest.elf \
  --data-root "/path/Halo Combat Evolved.app/Contents/Resources/GameData" \
  --host-ip "YOUR_LOCAL_IPV4" --timeout 150 --start-delay 25 --check-only
```

`--check-only` validates inputs/bindability and shows the command/settings without launching engines. Removing it acquires an exclusive local network-test lease and explicitly starts two bounded processes with isolated state, deterministic host/join/bot input and process-group cleanup. It uses an offline logical-address transport alias without changing protocol payloads or creating a system interface alias. The report separates socket traffic from two distinct live players, packet receipt and changing player positions. This reproducer requires real user-provided map data and is separate from asset-free CI. Run multiplayer map smoke tests serially or use the same `macos_network_test_lock.acquire_network_test_lock()` lease for their entire engine lifetime. The lease coordinates these harnesses; separately launched games can still occupy game endpoints and must be closed first. Missing first-run playlists/profile state is separate from a map-load or endpoint error. An actual same-Mac pair has joined and replicated manual movement between two native instances with clean exits. This reproducer establishes no 128-player or cross-platform compatibility claim.
